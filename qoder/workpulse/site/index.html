WorkPulse ·周报与项目记忆工作台

把散落的会议纪要、聊天记录和文档变成可追溯的项目记忆，每周自动生成带出处的周报。

看它如何工作 代码仓库

概览

WorkPulse 把项目里散落的文字收成两层东西：一层是可以逐条核对的证据，一层是可以反复使用的经验。周报不再靠回忆，而是从这两层里取数、拼装、标注出处。

  1. 01

    导入

    纪要、群聊、文档分块入库，自动抽出待办、决策与风险，原文一并保留。

  2. 02

    检索

    一条 SQL 同时算全文与向量，再过项目、类型、日期，权重按需要调。

  3. 03

    产出

    周报与任务视图，每条结论后面跟着 chunk 出处，随时可以点回去看原文。

资料形态
会议纪要 / 群聊记录 / 项目文档
存储与索引
seekdb v1.4.0 · FULLTEXT(ik) + VECTOR(hnsw)
记忆层
PowerContext 1.2.0 · basic memory 模式
服务
FastAPI · /search · /report · /evidence

痛点

三个问题通常出现在同一周里，指向同一件事：项目没有记忆。

  1. 01

    周报要从聊天记录里一条条拼

    周五下午翻群、翻文档，把做过的事重新回忆一遍，再组织成看起来像周报的文字。

  2. 02

    项目资料散落，找不到当初的决定和出处

    决定是在哪次评审、哪份纪要里定的？搜索结果只给关键词命中，不给上下文。

  3. 03

    任务进度要反复确认

    谁在做、做到哪、卡在哪，每次同步都要重新问一遍，答案还常常对不上。

信息都在，但不可检索、不可追溯、不可复用。

功能

六项能力串成一条线：资料进得来，证据查得到，周报与记忆留得住。

01

资料导入

把纪要、聊天记录和文档按语义分块入库，自动抽取待办、决策与风险，让资料从网盘里的文件变成可检索的条目。

documents → chunks · 待办 / 决策 / 风险

02

混合检索

seekdb 一条 SQL 同时算全文（ik 分词）与向量（HNSW），关键词与语义权重可调，每条结果都带 chunk 出处，解决搜不到、搜到也不敢用的问题。

MATCH ... AGAINST + cosine_distance

03

任务看板

负责人、截止日、状态一屏看清，状态变更自动写入项目记忆，不用再把进度重新问一遍。

tasks · status → memory

04

周报生成

按周聚合进展、风险与下周计划，每条都带 chunk#id · 文档 · 日期 引用，周五的活儿从翻记录变成点生成。

/report · 每条结论带出处

05

记忆复用

PowerContext 保存周报口径、决策与结论，下次生成时自动召回，同一个项目越用越准。

/v1/context/prepare

06

证据面板

把建表 DDL、最近一次检索 SQL 和 PowerContext 调用日志并排摆出来，任何一条结论都能当场核对，不用相信黑盒。

三份可核对的材料

  • 建表 DDL
  • 最近检索 SQL
  • 调用日志

技术

两个组件各承担一半：seekdb 保存可查的证据，PowerContext 保存可复用的经验。上层是 FastAPI 服务，使用 Qoder 开发。

seekdb v1.4.0

文档、分块、任务、报告与检索日志都在同一个库里。全文索引用 FULLTEXT INDEX ... WITH PARSER ik，向量索引用 VECTOR INDEX ... (DISTANCE=cosine, TYPE=hnsw, LIB=vsag)，项目、类型、日期作为结构化条件，和两路打分在同一条 SQL 里融合。

seekdb · chunks 表DDL 节选可横向滚动
CREATE TABLE chunks (
  chunk_id   BIGINT      NOT NULL AUTO_INCREMENT,
  doc_id     VARCHAR(64) NOT NULL,
  project    VARCHAR(64) NOT NULL,
  doc_type   VARCHAR(32) NOT NULL,
  doc_date   DATE        NOT NULL,
  chunk_text TEXT        NOT NULL,
  embedding  VECTOR(384),
  PRIMARY KEY (chunk_id),
  FULLTEXT INDEX ft_chunk (chunk_text)
    WITH PARSER ik,
  VECTOR INDEX vec_chunk (embedding)
    WITH (DISTANCE=cosine, TYPE=hnsw, LIB=vsag),
  KEY idx_chunk_filter (project, doc_type, doc_date)
) ORGANIZATION = HEAP;

PowerContext 1.2.0

HTTP API，basic memory 模式，无需模型 API。一个项目一个作用域，决策、进度、结论与偏好写进去，生成周报前做一次有界召回，Dashboard 可以人工核对记忆读写。

  • POST /v1/scopes 按项目建作用域
  • POST /v1/memory/remember 写入决策、进度、结论、偏好
  • POST /v1/context/prepare 生成前做有界召回
  • POST /v1/memory/entries/list 列出记忆条目，供人工核对

记忆按作用域隔离，召回有字节上限，不会把历史一口气塞进上下文。

一条 SQL 的三路融合

  • 全文 ik
  • 向量 HNSW
  • 结构化过滤

关键词走 FULLTEXT 索引，语义走 VECTOR 索引，项目、类型、日期走普通条件。两路分数按 ft_weight 加权（默认 0.45），向量权重自动取补数，排序、过滤、出处全部在同一条 SQL 里完成。

seekdb · hybrid searchSQL 节选可横向滚动
SELECT c.chunk_id, c.doc_id, d.title, c.doc_date,
       MATCH(c.chunk_text) AGAINST (%s) AS ft_score,
       cosine_distance(c.embedding, %s)   AS vec_dist,
       %s * LEAST(IFNULL(MATCH(c.chunk_text) AGAINST (%s), 0) * 2.2, 1.0)
     + %s * (1 - LEAST(IFNULL(cosine_distance(c.embedding, %s), 1.0), 1.0)) AS score
FROM chunks c
JOIN documents d ON d.doc_id = c.doc_id
WHERE c.project = %s
  AND c.doc_type IN (%s)
  AND c.doc_date BETWEEN %s AND %s
ORDER BY score DESC, c.chunk_id ASC
LIMIT %s;

< 20ms 本地实测：一条 SQL 端到端完成三路检索，结果直接带回 chunk 出处。

上手

三步在本机跑起来：seekdb 走 MySQL 协议，PowerContext 与 WorkPulse 各占一个端口。

  1. 启动 seekdb

    容器映射 2881，用 MySQL 协议连接；WorkPulse 首次启动时会自动建表与索引。

  2. 启动 PowerContext

    默认端口 8000，basic memory 模式，无需模型 API。

  3. 启动 WorkPulse

    FastAPI 服务，端口 8077。打开页面，导入资料，就可以生成第一份周报。

bash三条命令可横向滚动
docker run -d --name seekdb -p 2881:2881 quay.io/oceanbase/seekdb:latest
powercontext server run            # 端口 8000
python -m uvicorn app.main:app --port 8077
